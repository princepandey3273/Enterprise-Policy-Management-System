Project Specifics

Architecture
Can you explain the high-level architecture?
The project is a RAG pipeline. It uses Spring Boot for the backend, PostgreSQL + pgvector for semantic storage, and Google Gemini for embedding and generation. The flow is: Ingestion → Chunking → Vectorization → Storage → Retrieval → LLM Response.
Data Flow
What is the flow of data during PDF upload?
PDF → Apache PDFBox (Text Extraction) → Text Splitter (Chunking) → Gemini API (Embedding) → pgvector (Storage).

LLM & RAG Deep Dive

Reliability
How do you tackle Hallucinations?
Through Grounded Prompting. I explicitly tell the LLM to use only the provided context and to say "I don't know" if the answer isn't present. This transforms the LLM from a "creative writer" into a "document retriever."
Hyperparameters
What is Temperature?
Temperature controls randomness. For this project, we use Low Temperature (0.1-0.3) to ensure factual, consistent, and deterministic answers, which is critical for enterprise documents.

System Design & Scalability

Scaling
How to scale to 1 million documents?
1. Async Processing: Use Kafka/RabbitMQ for embedding generation.
2. ANN Search: Implement HNSW index in pgvector to replace exact search with Approximate Nearest Neighbor search.
3. Caching: Use Redis for common queries.
Optimization
How to handle massive PDFs?
Use a Recursive Character Text Splitter with Overlap. Overlapping ensures that context is not lost when a sentence is split between two chunks.

Problem Solving

Debugging
Describe a difficult bug you solved.
I faced a Vector Dimension Mismatch (Expected 768, got 3072). I diagnosed this by analyzing the pgvector SQLState error. I resolved it by updating the Java Entity definition and performing a schema migration to align the DB with the Gemini API's output.
ALTER TABLE document_chunks ALTER COLUMN embedding TYPE vector(3072);
